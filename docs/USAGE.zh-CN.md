## 安装与 macOS 安全提示

请先阅读[下载与安装说明](DOWNLOAD.zh-CN.md)。当前公开应用使用临时签名，**尚未通过 Apple 公证**，可能被 macOS 阻止打开。说明中提供了源码构建方法。构建测试与校验和不是恶意软件扫描，本地构建也不等于 Apple 公证通过。

## 用 Codex 导入工具

点击**导入 → 复制 Codex 提示词**，粘贴到 Mac 上的 Codex，并指定它可以查看的文件夹。导入前，核对它配对的启动和结束脚本。Codex 会生成 UTF-8 编码的 `.mungtools` 配置文件，再用工具箱打开。也可以通过**导入 → 选择文件**手动导入。

导入只添加配置，不会运行命令或修改脚本。工具箱会先验证整个文件，再保存；再次导入同一个 `.mungtools` 文件时，会跳过完全相同的条目，同 ID 但内容冲突的条目会被拒绝，已有工具会保留。文件格式与查找规则见 [Codex 导入说明](CODEX-IMPORT.md)。

此流程使用你已有的 Codex，并需要本地文件夹访问权限。工具箱没有内置 AI 服务、Codex 账户连接或 API Key 设置。

## 手动添加工具

1. 选择**新建工具**，填写名称。
2. 选择启动脚本，或填写 Shell 命令。
3. 设置工作目录。首次选择脚本时，若工作目录为空，会自动填入脚本所在文件夹。
4. 按需配置结束脚本或命令。未配置时，工具箱只能结束自己在当前会话中启动且仍持有的进程组。
5. 按需填写 HTTP 或 HTTPS 网址，然后保存。

脚本留在原位置。保存或删除工具不会修改脚本内容或执行权限。脚本文件需要可执行权限和有效的解释器声明，例如 `#!/bin/zsh`。也可以选择 **Shell 命令**并明确调用解释器，例如：

```sh
/bin/zsh '/path/to/Start.command'
```

Shell 命令通过 `/bin/zsh -lc` 执行。使用绝对路径，或相对于工作目录的路径。命令使用你的用户权限执行，请只添加你信任的命令。

打开工具箱时，不会自动启动工具。修改工具配置前，请先结束由工具箱管理的进程。未保存的草稿会保留在当前应用会话中。

## 日常操作

- 点击绿色**启动**按钮。在当前会话启动过工具后，结束按钮才会启用。
- 工具运行期间，启动按钮为灰色，**结束**按钮为红色。正在结束时，两者均不可用。
- 点击列表中的图钉，或按 **⌘P**，将常用工具放在最上方。重新打开应用后，置顶状态仍会保留，也会随配置导入和导出。
- 点击菜单栏图标，显示或隐藏窗口；右键显示快捷操作。
- 右上角的 **×** 只隐藏窗口，不会保存草稿、结束工具或退出工具箱。
- 点击地球按钮切换英文和简体中文。工具名称、路径、命令及已有日志保持原样。

## 状态与结束行为

| 状态 | 含义 |
| --- | --- |
| 就绪 | 当前会话尚未管理该工具。通过其他方式启动的服务可能仍在运行。 |
| 运行中 | 由工具箱启动的进程尚未退出。 |
| 启动命令已完成 | 启动命令正常退出，但另行打开的应用或服务可能继续运行。当前会话仍可执行已配置的结束命令。 |
| 需要检查 | 命令失败或需要检查，请查看日志。 |

结束操作先执行你配置的命令。成功后，如果当前会话持有的启动进程组仍在运行，会向其发送 TERM。未配置结束命令时，则直接发送 TERM 并等待。**强制结束**需要单独确认，工具箱不会自动升级为强制结束。如果结束失败，可以检查日志后重试。

脱离当前会话、打开终端或启动外部服务的命令，需要配置自己的结束命令。工具箱不会猜测应该结束哪个外部进程。如果几个工具共用一个服务，结束该服务可能影响它们全部。

退出时，可以先结束当前会话启动过的工具；不会自动对从未在此启动的工具执行结束命令。重新打开工具箱不会接管旧进程 ID：启动按钮重新可用，在这里再次启动后，结束按钮才会启用。需要时，请让启动脚本自行处理服务已在运行的情况。界面状态反映命令执行情况，不代表对外部服务的健康检查。

## 本地数据与分享

```text
~/Library/Application Support/MungTools/
  tools.json
  logs/<tool-id>.log
```

配置与日志保存在本机，工具箱不会同步它们。你配置的命令可以联网，其输出保存在本地日志中。导出的配置包含命令文本和本地路径，分享前请先检查内容。

日志查看器显示最后 64 KiB。超过 10 MiB 的日志在下次启动时轮转为 `.log.1`；正在运行的命令仍保留输出。配置以原子方式写入。损坏的配置会显示错误，并在下次保存前备份为 `tools.corrupt-*.json`。界面语言保存在 macOS 偏好设置中。

## 开发

需要 **Apple 芯片 Mac、macOS 14 或更新版本**，以及包含 Swift 编译器的 Apple 命令行工具。完整 Xcode 为可选项，无需第三方运行时。

```sh
./build.sh
"dist/Mung Tools.app/Contents/MacOS/MungTools" --self-test
./install.sh
```

构建脚本使用 `xcrun swiftc`，在 `dist/` 中生成使用临时签名的应用。安装脚本将其复制到 `~/Applications/Mung Tools.app` 并打开。使用 `./install.sh --no-open` 可仅安装。已有配置会保留；同名但属于其他程序的应用不会被覆盖。

自检使用临时模拟工具，不会启动或结束你配置的工具。测试界面时，可以指定独立的数据目录：

```sh
"dist/Mung Tools.app/Contents/MacOS/MungTools" --data-dir /tmp/mung-tools-demo
```

构建本地候选发布包：

```sh
./package-release.sh
```

脚本会构建应用，并在 `dist/releases/` 生成 `MungTools-macOS-arm64.dmg`、`MungTools-macOS-arm64.zip`、`MungTools-source.zip`、`SHA256SUMS` 和 `RELEASE-STATUS.plist`。应用包包含 **Mung Tools.app**，不包含你的配置或脚本。

这些是未公证的开发包，`publicReleaseReady` 为 `false`。本项目的公开发布验证流程要求完成 Developer ID 签名、Apple 公证和 Gatekeeper 验证，详见[公证流程](NOTARIZATION.md)。校验和与测试通过不能代替这些检查。

仅打包源码：

```sh
./package-source.sh
```

脚本生成 `dist/releases/MungTools-source.zip`，顶层目录为 `MungTools/`。打包只包含公开文件白名单内的内容，并检查归档清单。本地配置、日志、生成的应用、缓存、与本机相关的 `ManagedScripts`、录音及模型均不包含在内。
